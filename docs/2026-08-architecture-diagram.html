Infrastructure reference — staging

Where OpenSign actually runs

Migrated off a self-hosted box behind a personal domain (IT kept flagging it as newly-registered and blocking it) onto six free-tier services, wired together by two git remotes. This is the current shape of it.

Every address, in one place

No production domain anywhere in this stack on purpose — each host's own subdomain (*.vercel.app, *.onrender.com) is old enough that the corporate firewall doesn't flag it the way it flagged the personal domain.

LayerServiceRoleAddress
frontend Vercel Serves the built React app. All REACT_APP_* config is baked in at build time, not read at runtime. open-sign-ruby.vercel.app
backend Render Parse Server + Express. Free tier — sleeps after 15 min idle, ~30–60s cold start. opensign-jnjk.onrender.com
database MongoDB Atlas Documents, users, sessions. Free M0 cluster; network access opened to 0.0.0.0/0 for Render. cluster0.r7voerq.mongodb.net
storage Cloudflare R2 Uploaded files, signed PDFs, profile pictures. Persistent — survives a Render redeploy, unlike local disk. pub-e0f1672a…r2.dev
email Resend Sends via HTTPS, not SMTP — Render blocks outbound SMTP entirely on the free tier. Sandbox sender only sends to the account owner until a domain is verified. api.resend.com
source GitHub Primary repo. Pushing staging auto-deploys both Vercel and Render. github.com/pairat3000/OpenSign
Zero fixed cost across the stack — every service above is on its free tier, and none of them required a card except Cloudflare (R2 billing must be enabled to use it, though usage stays at $0 inside the 10GB free allowance). The only thing this setup can't yet do is send real signer-invite emails to third parties — that needs a verified sending domain on Resend.
